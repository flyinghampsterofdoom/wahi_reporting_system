Implemented
- Publication requires ingredients with displayable numeric measurements and units. Preparation,
  garnish and glassware are optional; existing instruction data remains in drafts and immutable
  versions. Structural limits, source-reference validation, permissions, concurrency and atomic
  historical publication remain enforced. Validation errors identify affected components/ingredients.
- Bartender rendering contains the recipe name and ingredient quantities, units and names, with
  expandable nested ingredient groups. Yields, instructions, ingredient notes, costing and source
  metadata are omitted. The API service projection removes administrative/provenance fields without
  modifying the stored publication. The same renderer handles previews and older cached documents.
- Management uses compact four-column ingredient tables with inline edits, add/remove, keyboard,
  pointer and touch ordering. Notes, exact original values and technical diagnostics are collapsed.
  Nested groups start collapsed. Secondary toolbar controls remain available under More actions.
- Decimal display removes padding and converts legacy fractions to decimals. Ambiguous long
  zero/nine residue and nonterminating fractions use an explicit approximation marker. Exact strings
  remain saved and available in diagnostics. Tiny nonzero values and other meaningful precision are
  preserved. Rendering, saving unrelated edits and formatting on blur do not normalize saved values.
  Readable unit aliases likewise do not rewrite saved units. Only explicit ingredient edits change
  the independent service document; no unit conversion or costing operation is invoked.
- Import remains one-way copying. Repeat imports into a populated editor require confirmation and
  append independent copies. No existing component or publication is replaced by import. No active
  synchronization, reverse write path, source-refresh subscription or overwrite endpoint was added.
