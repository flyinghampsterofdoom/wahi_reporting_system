B. PHASE 2 IMPLEMENTATION
Persistence: recipe_book_entries, recipe_book_drafts, recipe_book_versions, recipe_book_events,
and recipe_book_media. Entry identities are independent of costing identities and titles.
The published pointer has a composite foreign key requiring the version to belong to that entry.
Database triggers prohibit publication/event UPDATE and DELETE. The existing global user-deletion
restriction remains; a new station guard protects designated usernames and role assignments.

Services: create, save, publish, classify, archive/restore, recover a prior version into a draft,
management entry lookup, published reads, history, source-title search and recursive source snapshot.
Each mutation uses current active database role checks, row locking, optimistic entry version,
and transactionally required audit. A failed audit rolls back the entire operation. Saved drafts
cannot change the published pointer. Publishing requires explicit confirmation of the current
saved version. Recovery does not silently republish or unarchive. Archive changes service state
only, leaving every domain recipe, cost basis, mapping and historical cost intact.

Well foundations: existing named-user create/setup/reset/session services now support RECIPE_ONLY.
well.one and well.two require this role and cannot be renamed. Admin retains provisioning and
reset controls. No production station accounts were created. Only disposable tests provisioned
synthetic stations. A server default-deny gate permits only session metadata, logout, published
Recipe Book content and its policy contract. All unrelated APIs, administrative tools, drafts,
sources, history and editing/publishing are denied before their handlers. Forged roles/preview
headers cannot bypass the gate. Two named sessions remain independent when one logs out.

Navigation: Recipe Book appears in the existing primary sidebar; Builder destination is limited
to edit-capable users. Stations see Recipe Book only and always land there despite stale/forged
URL hashes. The destination pages intentionally expose Phase 2 foundation status; complete
bartender interaction and visual editing remain later work.

Shared renderer: a browser/Node module with escaped text, standard left-aligned bold section
headings, bold quantity/unit before regular-weight ingredient name, fixed whole-item indentation,
unit display labels, retained decimal formatting and collapsed/expanded recipe components.
The renderer is loaded in the application and ready for the later preview and service layout.
